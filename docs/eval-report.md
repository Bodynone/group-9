## 样本与真值

`samples/benchmark/S01.txt` 至 `S20.txt` 参照现有 S1/S2 的任务单结构和项目现行 `2026-v1` 量表撰写，正文为 1,507–2,547 字符，覆盖优秀标杆 3 份、中等常规 3 份、严重残缺 3 份、对抗注入 3 份、混合边界 8 份。`benchmark.json` 记录量表版本、每维暂定档位和分数、关键采分点、全文 SHA-256。优秀组总分 97–100，中等组 70–74.5，严重残缺组 45.5–48.5，对抗组 9–16.5。对抗样本自身的需求内容也有明显缺陷；不得仅因出现攻击语句就直接判零。

真值由量表规则编制，状态是 **暂定、未经独立教师复核**。正式用于“专家一致率”之前，需要至少一名未参与编写的教师逐维复核，记录争议和最终标签。评测脚本在本地使用这些标签校验数据完整性，模型输入仅包含作业正文、量表和当前调用的工具协议，不含标签或答案。标签尚未用于评分一致率统计。

样本文本通过 `.gitattributes` 固定为 UTF-8/LF。脚本直接读取原始字节计算 SHA-256，不自动归一化换行或删除 BOM；Windows 检出也应与 `benchmark.json` 的哈希一致，人工改动换行后必须重新核对，不能用文本读取时的隐式换行转换掩盖差异。

## 实验方式与指标口径

在仓库根目录安装后端依赖并设置模型参数后运行：

```bash
uv sync --project backend
uv run --project backend python backend/scripts/ablation_study.py --check
uv run --project backend python backend/scripts/ablation_study.py --samples 20
```

直接 Prompt 只传量表与文本，不提供工具；工具辅助模式允许读取量表、定位原文、Decimal 计分，但不提供 `validate_draft`；完整模式执行现有 `AgentRunner` 的四类工具与最多两轮修正。工具辅助模式会保留提供方要求的 `reasoning_content` 对话字段，但不把内部推理写入结果文件。三组使用相同模型、相同样本、同一量表和相同的任务总超时；逐份顺序执行，并发度为 1。运行后本报告会自动替换成实测表格，逐样本草稿、输入哈希、指标及运行参数保存为 `docs/eval-results.json`。该文件只保存模型生成草稿，不形成已确认成绩；完整模式使用内存数据库，不写 Demo 数据库。任一组出现请求、解析或执行错误时，仍保存其余结果，最终进程退出码为 1，错误文本会先脱敏。

三组还存在提示词、输出协议和护栏差异，因此这是系统方案比较，不能把全部差异归因于是否启用校验工具。

算术准确率与格式合规率以全部所选样本为分母，失败输出记为未通过。算术准确指报告总分等于六维分项之和；格式合规指 A–F 六维齐全、档位合法、理由非空、分数可解析、证据为数组。证据真实率以输出引用条数为分母，字符串引用须在原文中逐字出现；定位对象还须满足 Unicode codepoint 切片完全一致、范围合法和段落正确。无引用时显示“无引用”，不按 100% 处理。耗时包含模型与工具调用。Token 仅在所有样本成功且每次调用均提供有效 `usage` 时统计。以上机械指标不等于教师评分准确率，也不能替代后端对档位分值与证据来源的完整校验。
