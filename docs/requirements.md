# FR-01：单份作业的可追溯评分草稿与教师复核

修订日期：2026-10-13。依据：[9_1_v2.pdf](../9_1_v2.pdf) 的 FR-01、验收场景与质量约束（第 3-9 页），合成样本（第 6-7 页）及配套量表（第 12 页）。本次实现选择单份文本批改流程；课堂小测统计仅是待批改样本中的项目，不是本系统要实现的功能。

本文件将“如何验证”写为可执行检查：固定输入和故障条件，触发具体操作，观察输出与状态，逐项判定，并保存可映射到本次任务的证据。源任务单尚未完成的教师核定、真实互评和实际评分仍待完成；实现与程序测试不能代填这些记录。

## 1. 范围与固定规则

- 用户：本地使用的一名课程教师；提交前由教师去除直接身份信息。
- 流程：输入匿名作业 → 单 Agent 取证与六维草稿 → 工具校验及有限修正 → 教师逐维复核 → 明确确认 → 保存并导出 JSON。
- Agent 只访问当前作业和固定量表，四类工具均为普通程序，不构成其他 Agent。原文中的指令属于待评价数据，不能覆盖量表、工具权限或教师确认要求。
- 不含批量导入、PDF/OCR、自由量表、跨课程、登录权限、正式成绩发布和多 Agent 协作。

冻结量表版本为 `af-2026-10-09-v1`，来源为源 PDF 第 12 页。每维只能取 `100`、`70`、`30`、`0` 四个档位；`0` 只适用于相关内容整体缺失。零散缺项与争议由模型提出核查事项，再由教师判断。

| 维度 | 名称 | 满分 | 100%：清楚可执行 | 70%：基本成立 | 30%：尚不清楚 |
|---|---|---:|---|---|---|
| A | 用户、依据与范围 | 15 | 用户困难与功能对应；来源、现状与排除项清楚 | 用户功能明确，来源或边界有一项缺失 | 仅列功能／愿望，混淆现状与建议 |
| B | 需求表达 | 20 | 编号、前提、动作、可见结果齐全且一致 | 主体结果明确，前提或动作有歧义 | 仅写智能、方便、快或技术方案 |
| C | 验收可执行性 | 30 | 至少三场景覆盖正常、差异／边界、异常；输入、预期、判据、判定人、样本、数字来源齐全 | 三场景多数可判定，但关键字段或数字来源缺失 | 只有正常流程或无法复核的效果承诺 |
| D | 行为依据与边界 | 15 | 输入／规则与输出可追溯，变化有理由；普通功能边界或 AI 失败与人工核查明确 | 解释部分依据边界，但关键变化或失败结果未说明 | 输出变化无依据或异常与需求无关 |
| E | AI 协作与人工判断 | 10 | 有问题、建议、采纳／拒绝理由与具体修改；不可用时有人工审查替代记录 | 有记录，决策理由或改动对应不完整 | 仅写 AI 生成／未用，没有审查 |
| F | 互评修订与交接 | 10 | 有版本、成员责任、带证据的反馈与对应修订／合理拒绝 | 有反馈修订，缺版本、责任或处理理由 | 无法追踪反馈和改动 |

先找原文证据，再选档；分项 = 满分 × 档位 ÷ 100，总分用 Decimal 精确相加，允许半分，不向整数取整。A 的 70% 为 10.5、30% 为 4.5。六维满分合计 100。课堂形成性反馈不自动等同课程正式成绩。

## 2. 修改前后与功能需求

以下“修改前”引用源任务单的表达；“修改后”补足检查对象、方法和证据，保留原有需求方向与数字来源。

| 原表达 | 修订后的验证表达 |
|---|---|
| “每维证据可在 S1 定位” | 对每条非缺失引用检查 `text[start:end] == quote`；位置与输入 SHA-256 一致，错误或旧输入引用不得通过。内容能否支持档位另由教师核定。 |
| “摘要可映射到本次输入与量表版本” | 摘要必须含任务编号、原输入的 UTF-8 SHA-256、量表版本、六维分析清单、真实工具名与结果、每次校验结论、修正轮次及停止状态；逐项与任务数据比对。 |
| “原作业与量表版本逐字保留率为 100%” | 对 T3a/T3c 失败前后获取的原输入进行逐字比较和 SHA-256 比较；量表版本必须相同；重试使用同一原文，无需重新粘贴。 |
| “最多进行 2 轮修正” | T3b 必须记录首次校验失败、B 维重新定位、一次修正、第二次校验通过；T3c 必须恰好两轮修正、三次失败校验后停止，不能启动第三轮修正。 |
| “不产生新的有效评分或正式成绩” | 失败任务不可提供有效完整草稿；确认和最终导出必须拒绝。待复核任务不可确认，六维逐项复核完成后才能保存确认记录。 |
| “15/15 次均满足全部判据才通过” | 五个固定场景各重复三次，每次逐项检查全部判据并保存输入、输出、故障配置及执行摘要；程序测试与真实模型结果分栏记录，不推断对其他作业的泛化效果。 |

### FR-01：生成、校验与复核

**前提与触发：**教师提供非空匿名作业文本并选择冻结量表，点击“生成评分草稿”。系统保存原始文本，不擅自删改空格或换行；仅空白输入被拒绝。

**成功结果：**系统提供 A-F 六维名称、满分、建议档位、分项得分、证据原文及定位、简短理由、待核查事项、总分、输入版本和量表版本，状态显示“评分草稿，待教师确认”。执行摘要能够证明量表读取、原文定位、精确计分和草稿校验实际执行，且最终校验通过。

**生成与停止：**Agent 建立六维分析清单，自主选择取证次序，调用四类工具。首次草稿必须校验；校验失败最多修正两轮，每轮再次校验，即最多三次校验。通过立即交教师复核，持续失败达到上限停止。模型或工具运行错误立即失败。另设最多 24 次模型请求及任务最长 300 秒，超限保留输入并报告失败。

**失败结果：**显示失败原因及失败的模型／工具，不展示为有效完整草稿。原文和量表版本保持一致，提供重试和人工批改入口。重试创建新的关联任务，`parent_id` 指向旧失败任务；原文与量表版本不变，旧失败任务和摘要保留。

**复核确认：**教师逐维采纳或修改档位与理由，后端重新计算分项及总分。六维均已复核且理由完整后，教师明确确认，系统生成唯一记录编号。确认前不得保存为最终评分；重复确认返回同一记录。人工接管提供同样的六维评分与确认流程，并保留 Agent 失败原因及已有建议。

**持久化：**SQLite 分开保存原始文本、模型建议、教师修改、最终评分与执行摘要。刷新可恢复当前任务；服务重启将未完成任务标记为失败，保留输入并允许重试。输入改变后必须创建新任务并重新取证，不能沿用旧版本引用。导出为已确认记录的 JSON。

### 质量约束与检查

| 编号 | 可观察要求 | 检查方法与通过标准 | 来源 |
|---|---|---|---|
| NFR-01 数据保留 | 工具错误、校验持续失败和重启后，原文与量表保持原样 | 失败前后逐字及 SHA-256 比较；T3a/T3c 各三次全部一致，解除故障后无需再粘贴即可重试 | 源任务单的 100% 保留目标；重启持久化为本次实现补充 |
| NFR-02 有限执行 | 最多两轮修正、三次校验；通过或失败上限后停止 | 对真实摘要计数；T3b 为 1/2、T3c 为 2/3，且停止后无后续模型／工具调用 | 源任务单团队拟定值 |
| NFR-03 执行预算 | 模型请求最多 24 次，任务不超过 300 秒预算 | 可控客户端模拟超限／超时，检查失败、保留输入和无有效新草稿 | 本次实现的保护上限，不是性能承诺 |
| NFR-04 教师控制 | 生成结果始终待确认，Agent 没有成绩发布动作 | 未完成复核时确认被拒绝；改档位后由后端重算；重复确认不重复写入 | 源任务单权限边界 |
| NFR-05 可追溯 | 工具输出与当前任务、输入、量表一致 | 检查原文定位区间、输入 SHA-256、工具调用、模型请求和校验记录；旧版本引用校验失败 | 源任务单交接数据要求 |

## 3. 可执行验收场景

### 固定输入与判定职责

- `samples/S1.txt` 是源 PDF 第 6-7 页“【S1 开始】…【S1 结束】”完整正文，仅合并 PDF 的视觉换行，不加入参考结果；合成身份与协作经过仍明确标注为模拟数据。
- `samples/S2.txt` 仅删除 S1 中“【C 区开始】”与“【C 区结束】”间的正文，保留其余文字和标记。
- `samples/expected.json` 单独保存参考档位、分数、输入 SHA-256 和故障定义；不得放入模型输入。参考答案来自源任务单和量表，仍须真实教师／邻组核定，当前 `human_approval` 为 `pending`。
- 验收人执行操作，本组核查人检查证据和计算；语义／档位争议由教师裁定。真实姓名与核定结论填写在 `docs/acceptance-record.md`，不得使用样本中的匿名合成角色代替。

| 场景 | 输入与前提 | 操作 | 预期结果与全部通过判据 | 检查方法与证据 | 执行状态 |
|---|---|---|---|---|---|
| T1 正常 | S1，固定量表；模型和工具可用 | 提交 S1，待结束，展开摘要 | 六维档位均 100；分项 15、20、30、15、10、10，总分 100；引用逐字定位；四类工具实际执行；校验通过；状态待教师确认 | 保存原文、任务编号、SHA-256、输出／截图和摘要；比对参考结果并人工核查依据 | 受控 3/3 通过；Qwen 真实 S1 总分 100；当前 DeepSeek S1 限流失败待重试；人工核定 pending |
| T2 缺失边界 | S2，仅 C 区正文清空 | 提交 S2，查看 C 定位与结果 | C=0，缺失提示“该部分未提供”，其余五维与 T1 相同，总分 70；无已删除文字引用；同一量表与当前输入摘要；校验通过，待确认 | 与 S1 比对证明只删 C；逐字检查引用；保存 S2 输出、分数及摘要 | 受控 3/3 通过；Qwen 三次超时保留历史；DeepSeek 真实 S2 为 70，11/11 机械检查通过；人工核定 pending |
| T3a 工具故障 | S1；测试注入定位工具首次 503 | 启动，检查失败；解除注入后重试 | 立即失败，指出定位工具；原文及量表保留，无有效新草稿；无需粘贴即可重试，恢复后满足 T1 | 保存故障配置、失败输出、原文前后比较与新旧摘要 | 受控 3/3 通过；真实模型故障注入未执行 |
| T3b 一次修正 | S1；仅首次草稿 B 引用替换为 `【不存在的证据 QX-001】` | 启动，检查首次失败、补查及第二次校验 | 首次引用校验失败；Agent 重新定位 B；恰好一次修正、两次校验后通过，最终分数同 T1；错误草稿不可作为有效结果 | 保存注入点、每次校验错误、B 补查工具调用、修正轮次、有效输出 | 受控 3/3 通过；真实模型故障注入未执行 |
| T3c 持续失败 | S1；首次及两轮修正草稿持续注入同一 B 错引用 | 启动至停止，检查调用计数和人工入口 | 恰好两轮修正、三次校验失败后停止；无第三轮修正；原文和量表保留，无有效新草稿／最终评分；可重试或人工接管 | 保存三次失败错误、全部摘要、输入前后比较、停止状态和人工入口截图 | 受控 3/3 通过；真实模型故障注入未执行 |

每次场景的全部判据必须满足才记“通过”；缺一项即不通过。五个场景各三次，共 15 次，阈值为 15/15。该数字是团队拟定的固定样本流程验收标准，不是评分准确率、模型泛化能力或源任务单实际成绩。

### 程序验收与人工核定分开记录

1. 使用可控模型测试替身驱动真实执行引擎和四类工具；替身只控制模型响应与故障，用于可重复验证计分、引用、调用次数、失败恢复和状态。它不能证明真实模型会选对档位。
2. 配置真实服务后单独执行模型工具调用和 S1/S2 评分检查。保存实际服务、模型、时间、输入版本、输出和摘要；任何不符合预期的结果按实记录。不能将自动测试结果填入真实模型栏。
3. 教师核对引用是否真正支持档位、遗漏和歧义是否需要调整，并填写采纳／拒绝理由。程序校验通过只表明结构和计算一致，不代表评分语义已获教师认可。
4. 人工核定前，S1=100 与 S2=70 是拟定参考；源任务单的真实互评、最终评价及人工核查仍待完成。S1 内部的 9/9 指标是样本所描述项目的模拟验收，与本系统 15/15 流程验收分开。

## 4. 接口与证据保存约定

| 接口 | 行为 |
|---|---|
| `GET /api/rubric` | 读取冻结量表、权重和合法档位 |
| `POST /api/tasks` | 提交 `{text, rubric_version}`，保存原文，返回任务编号；后台运行 |
| `GET /api/tasks/{id}` | 查询状态、原文、输入版本、草稿／复核结果、错误与摘要 |
| `POST /api/tasks/{id}/retry` | 仅失败任务可重试；用保留输入创建新任务，`parent_id` 指向旧任务，保留失败证据 |
| `POST /api/tasks/{id}/manual` | 接管到人工六维评分 |
| `PATCH /api/tasks/{id}/review` | 提交 `{input_version, dimensions: [{id, level, reason, reviewed}]}`；后端重算 |
| `POST /api/tasks/{id}/confirm` | 检查六维复核完成，保存唯一已确认记录 |
| `GET /api/tasks/{id}/export` | 导出已确认记录 JSON |

原始输入版本取原文 UTF-8 字节的 SHA-256；引用位置使用原文本字符区间，左闭右开。摘要关联任务编号、输入版本、量表版本和运行记录。数据库为 `backend/data/grading.sqlite3`。API 密钥仅由后端读取，不进入页面、摘要、导出或测试记录。

按“场景_第几次”保存输入、量表、输出／截图、逐项判定和执行摘要；故障场景再保存配置与输入前后比对。测试注入只存在于测试环境，不提供生产 HTTP 故障接口。

真实模型检查分开记录服务、模型与历史：此前 HTTP 403 后，Qwen 的 S1 实测形成总分 100、待确认草稿；Qwen 的 S2 三次超时保留历史。随后根 `.env` 被用户／外部切换至 DeepSeek，本次实现未修改 `.env`；新配置的 S2 得到 70 分并通过 11/11 机械检查，S1 因 429 限流无有效草稿。S1 与 S2 的成功来自不同模型，不能视为同一模型的完整验收；当前 DeepSeek S1 重试、教师核定与真实互评仍待完成。全部证据见 `docs/acceptance-record.md`。
